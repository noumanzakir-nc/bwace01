# Unit Test Execution — BW-ACE

## Run Unit Tests

### 1. Execute all unit tests (both units)
```
.venv\Scripts\python.exe -m pytest tests
```

### 2. Execute per-unit, if isolating a failure
```
.venv\Scripts\python.exe -m pytest tests\engine   # Unit 1 only
.venv\Scripts\python.exe -m pytest tests\app      # Unit 2 only
```

### 3. Review test results

**Actual result from a clean-install run performed for this document**:

```
73 passed in 9.74s
```

- **Expected**: 73 tests pass, 0 failures (56 in `tests/engine`, 17 in `tests/app`)
- **Test coverage**: no line-coverage tool is configured (not requested by NFR-7.x, which asks for reference-dataset assertions and view smoke tests rather than a coverage percentage). Coverage is qualitative: every pure engine function (C4–C9) has direct tests, `test_reference_dataset.py` binds all 13 Unit 1 Definition-of-Done criteria, and every Unit 2 view is exercised via `AppTest`.
- **Test report location**: console output only; no HTML/XML report is generated by default. Add `--junitxml=report.xml` if a CI pipeline needs a machine-readable report — not currently required.

### 4. Fix failing tests

If tests fail:
1. Run the failing file alone with `-v` for full output: `pytest tests\engine\test_X.py -v`
2. If the failure is in `test_reference_dataset.py`, treat it as a regression against `business-rules.md` §13's verified figures — do not adjust the test to match new output without re-verifying the business rule.
3. If the failure is in `tests/app`, check whether it is a Streamlit `AppTest` widget-key mismatch (a renamed `key=` in a widget will surface as `KeyError` in the test) versus a genuine rendering exception.
4. Fix the implementation, rerun.

## What This Test Suite Deliberately Does Not Cover

- Cross-platform execution of `run.sh` (not executable from this Windows environment — see `build-and-test-summary.md`)
- Manual visual/browser verification (the `AppTest` harness runs the Streamlit script without a browser; it confirms no exception and inspects rendered element values, not pixel appearance)
- Load/stress testing beyond the synthetic ~1,100-object headroom check recorded in `performance-test-instructions.md`
